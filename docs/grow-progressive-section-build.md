# /grow 章节分批建：把冷开约 1 秒的主线程死锁降到 0.4 秒级

> 一句话结论：用户报的「操作整个界面感觉不流畅」，量下来外壳（侧栏划过、搜索框、静置）**不是**瓶颈；
> 唯一能稳定复现的秒级阻塞是 **/grow 首次打开**——一次性建完 20 个章节会把主线程连续死住约 1 秒。
> 改法是把章节分成每批 5 节、批间留一帧空档补齐：最长一次冻结 **958~1033ms → 408~475ms**，
> 总开销与落定时间跟改前持平，落定后的 DOM 完全一致。

## 1. 排查路径：先证外壳无辜，再定位唯一阻塞点

### 1.1 外壳交互（`Temp/diag-shelf2-1.log`，整机低负载，货架 1 页与 8 页两档 A/B）

| 动作 | 货架 1 页 | 货架 8 页（DOM 11032） |
| --- | --- | --- |
| 划过 12 个菜单项（12/12 成功） | 长任务 **0 个 / 0ms** | 长任务 **0 个 / 0ms** |
| 搜索框打 10 个字（菜单项 91→3） | 1 个 / **134ms** | 2 个 / **349ms**（236+113） |
| 静置 3s（对照） | — | 长任务 **0 个 / 0ms** |

rAF 中位帧两档都是 8ms，JS 异常 0。⇒ 侧栏、搜索、静置都不构成「不流畅」；
货架从 1 页撑到 8 页只让搜索框从 134ms 涨到 349ms（亚秒级，且不是用户报的症状）。

### 1.2 各页冷开成本（`Temp/coldopen-debug-lowload.log`，每次整页重载＝冷开）

| 页面 | DOM 安静用时 | 长任务 |
| --- | --- | --- |
| 头像 Avatar | 645ms | **0 个 / 0ms** |
| 走马灯 Carousel | 638ms | 1 个 / 71ms |
| 虚拟化表格 TableV2 | 646ms | 1 个 / 145ms |
| **自研 / Grow** | **2642ms** | **13 个 / 2160ms，最大单个 831ms** |

CDP 同窗口对照：Grow 的 `task 2.44s / script 1.3s / layout 32 次 0.21s`，其余三页 `task 0.23~0.36s`。
⇒ /grow 是唯一离群的页面，本页子树 4243 节点 / 228 个 svg / 34 个 `el-chart-grow`。

Release 同口径复测（`Temp/coldopen-release-lowload.log`）：合计 2771ms、最大单个 1619ms。
⇒ **换 Release/AOT 不是杠杆**，Debug 与 Release 同量级，问题在「一次建太多」而不是「跑得慢」。

## 2. 改法

`demo/Element.Blazor.Demo/Pages/GrowDemo.razor`：

- 20 个 `<div class="demo-section">` 各加一道闸门 `@if (builtSections > k)`，闸门放在 `<h3>` **之后**
  ⇒ 章节标题不参与闸门，页面骨架、锚点、滚动目标一进来就在。
- `builtSections` 初值 `GrowEagerSections = 2`（首屏先建前 2 节）。
- `OnAfterRenderAsync(firstRender)` 里起一个泵：每 `Task.Delay(60)` 建 `GrowSectionChunk = 5` 节，
  `InvokeAsync(StateHasChanged)` 提交，直到 20 节建齐。
- 泵用**独立** `CancellationTokenSource`，`IDisposable.Dispose()` 里 `Cancel()`
  ⇒ 页签被关掉/被货架淘汰时停住，不再往已卸载的渲染器上排队（遵循本仓异步自动关闭的既定写法）。

## 4. 作废的测量（连同作废理由一起留档）

   一次是 **958/1033/967/1008ms** —— 同一份代码差 **2.8 倍**。所以只认同窗口三臂，
   早先写在源码注释里的「2160ms/831ms」「2666→11005ms」等跨窗口数字已全部换成第 3 节的同窗口数字。
   注：18:2x 那次「一节一帧」臂的日志被后来的 runB 覆盖、未留存（只在会话转录里），一并作废。
2. **`grow-after-k5-samewindow.log` 第 4 轮作废**，且日志里当时写的「计时可信」是错的：

   不是主线程在算。仪器判据当时只看「中位帧 ≤100ms + `vis=visible`」，中位帧 9ms 蒙混过关。
   **判据已补**：最大帧间隔若超出最大长任务 500ms 以上 ⇒ 判「计时不可信」，本轮时长读数不作结论。
   更正已追加进该日志尾部。
3. **「20 节正文全建齐」这个读数不可信，本文一律不引用**。它用 `每个 .demo-section 的 children.length > 1`
   判定，而「一节一帧」臂量到 351~575ms —— 泵至少要 18×60ms=1080ms 才可能建齐，物理上不可能。

## 5. 明确没做的（与否决理由）

- **没动 keep-alive 货架语义**（`KeepAliveRouteView` / `MaxCache = 30` / `CachedPage.ShouldRender`）。
  「开的页越多、开新页越慢」当时只有 `Temp/diag-lag3-1.log` 一条出过这个形状（TableV2 145→752ms、Grow 2160→3979ms），
  而那一轮帧节奏塌过（同轮 心跳135/帧2）、又属跨窗口数字，按第 4 节第 1 条不作数 ⇒ 本批用同 boot 配对阶梯重测，
  **结论是这条放大不成立**，见第 8 节。改上限等于反转用户先前批准的设计，实测无收益就更不该动。
- **没做真·视口按需渲染**（只建看得见的章节）。那样总活儿才真能降，但落定 DOM 就不再等于改前，
  24 个打到 /grow 的常驻探针会因为深层元素不存在而红 —— 本次选的是「内容中性」这条约束。
  第 8.4 节量到了这条约束现在的价格：/grow 的活儿全在开页后 0~9s 内跑完，最长单个长任务 833~918ms。
- **没改库侧组件**（例如让 34 个 `el-chart-grow` 各自可见时才画）。范围只限 /grow 演示页。

## 8. 批次㉓ 收尾复测（2026-10-12）：④「已开页数放大开页成本」不成立，并把两条噪音点名

本轮**没有产品代码改动**，只做测量与量具更正（同批还更正了一条常驻探针的旋钮定位方式，见 `docs/testing-guards.md` §3.7 的批次㉓ 复核表）。整机负载一直在 58~76% CPU（用户自己的 devenv 在跑），
所以每条读数都带当轮 CPU 值，且只下同窗口内可比的数字。

### 8.1 为什么要重测第 ④ 条

`Temp/diag-lag3-1.log` 是它唯一的出处（TableV2 单独冷开 145ms → 货架 6 页时 752ms；Grow 2160ms → 3979ms），
而那一轮里 Grow 是「帧 8 个 / 掉帧 6」「心跳150」、TableV2 是「帧 2 个 / 首变 1146ms」——
正是本文第 1 页撤回「~1000ms 停顿」时用的同一种形态：**帧节奏塌过的轮次不能量时长**。
跨 boot 对比又按第 4 节第 1 条一律作废，所以那条账一直没结。

### 8.2 方法：同一次启动内的配对阶梯（不做跨 boot 对比）

探针 `Temp/diag-shelf4.cjs`，日志 `Temp/diag-shelf4-1.log`。一次 boot 里按固定顺序连开 13 个页，
逐个量「点击菜单 → 该页 DOM 连续安静」＋窗口内长任务；换另一轮用**反序**，
于是**同一份页面内容**在两轮里分别落在货架第 k 位与第 14−k 位：

- 轮 A：12 个轻页正序，/grow 排第 13 位；轮 B：/grow 第 1 位，轻页反序；轮 C：同 A（看可重复性）。
- 配对差＝同一页在两个档位下的成本差，**页面自身内容成本自动抵消**，档位差才是货架差。
- 每轮先过空闲门（中位帧 ≤20ms 且 `vis=visible`），每臂再核「最大帧间隔 ≤ 最大长任务 + 500ms」，
  不满足就标「计时不可信」。三臂 39 个读数点**全部判「计时可信」**（中位帧一律 8.3ms），JS 异常 0。

- 顺带说明第 3 节那条「静置 3s 长任务 0 个」的对照没测错：3s 桶本来就落在长任务之前，
  本轮把观测窗拉到 45s 才看见这条 1~2s 一次的属性写噪音。

### 8.6 本轮作废的量具（连同作废证据）

`Temp/diag-growfirst.cjs`（日志 `Temp/diag-growfirst-1.log`）用 Node 侧 50ms 轮询读 DOM 来定「变更时刻」，
铁证是**三组读数里 `T-menu` 与 `T-page` 一模一样**（1714/1440/1456ms 三个数两臂同时相等）——
`page.evaluate` 自己也要主线程空出来才能跑，所以它量到的是「主线程下一次可运行」而不是「DOM 变更时刻」。
该口径整条作废，改由页内 MutationObserver 打时间戳（8.4）。这条与本文第 4 节第 2 条是同一族坑，已补进 `docs/testing-guards.md` §3.23。
